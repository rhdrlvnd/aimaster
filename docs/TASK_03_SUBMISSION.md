# Task 3 — 시나리오 수립

- 수정일: 2026-10-26
- 과제명: 업무 인수인계 Agent
- 상태: 사용자 시나리오와 입출력·성공 기준 정의. 직접 제작한 예시 문서와 시나리오로 검증

## 1. 핵심 사용자 시나리오

모든 시나리오는 직접 제작한 업무 문서와 인수인계 데이터로 개발·평가합니다. 전임자(인계자)와 후임자(인수자)의 역할을 나누어 실행하고, AI가 제안한 결과와 사용자가 확정한 결과를 구분합니다. 평가 시에는 테스트 계정으로 인계자·인수자의 역할별 동작을 검증합니다. 전체 목록은 볼 수 있으나 상세 내용은 지정된 참여자만 접근합니다. 인수자는 확정된 내용만 조회하며 문서 등록이나 체크리스트 검토·수정 권한이 없습니다.

### 시나리오 1: 업무 문서로 인수인계 체크리스트 작성

- ID: SC-001
- 상황: 전임자가 담당 업무를 넘기기 위해 여러 업무 문서를 정리해야 합니다.
- 목표: 문서에서 인수인계할 핵심 업무를 추출하고 검토해 체크리스트를 확정합니다.
- 사전 조건: 인수인계 제목·담당 업무·기간·인수자 정보와 업무 문서가 준비되어 있고, 인계자 계정으로 접속했습니다. 문서 분석과 초안 생성을 위한 AI 연결이 설정되어 있습니다.

AI 활용

Word·Excel의 추출 내용을 보존하고 PPT 이미지는 AI가 축약 없이 정리합니다. 체크리스트 생성에는 이미지를 다시 보내지 않고 저장된 전체 문서 청크와 장표 정리 내용을 바탕으로 후임자에게 전달할 업무를 정리합니다. 생성한 초안은 프로그램의 형식·인용 검사를 거친 뒤 별도 AI 호출로 누락·중복·설명과 근거의 일치 여부를 재검토합니다. 검증 실패 시 직전 초안과 구체적인 이유를 전달해 다시 작성합니다. AI 재검토가 정확성을 보장하지는 않으며 업무 내용의 최종 판단은 인계자가 담당합니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 인계자가 인수인계 제목·담당 업무·기간·인수자를 입력합니다. | 본인을 인계자로 지정한 인수인계를 생성하고 자료를 구분해 저장합니다. | 생성한 사용자를 인계자로 지정 |
| 2 | 업무 문서 화면에서 하나 이상의 파일을 선택해 등록합니다. | 형식·용량을 검사하고 파일별로 텍스트·표를 추출합니다. PPT는 슬라이드 이미지로도 변환합니다. | 파일 확장자로 형식 확인 |
| 3 | 문서별 분석 진행 상황과 결과를 확인합니다. | 전체 내용 정리 → 청크 분할 → 벡터 임베딩 → ChromaDB 저장을 수행하고 실제 처리 결과를 표시합니다. | 분석 실패 문서는 다시 분석 가능 |
| 4 | 모든 문서의 분석이 끝나면 체크리스트 생성을 실행합니다. | 전체 저장 내용으로 업무 목록을 선정하고 소수 항목씩 작성합니다. 각 요청에도 전체 문서와 업무 목록을 전달합니다. | 진행 중인 단계 옆에 모델명과 진행 설명 표시 |
| 5 | 생성·검토 진행 상황을 확인합니다. | 프로그램이 형식·언어·인용·청크 연결·동일 제목 중복을 검사하고 AI가 내용을 재검토합니다. 전체 내용 검토 후 선행 업무와 관계 근거도 검증해 초안을 저장합니다. | 문제 항목을 제한된 횟수 안에서 보완. 끝까지 실패하면 기존 초안 유지 |
| 6 | 원문 근거를 확인하고 제목·설명·분류·중요도·선행 업무를 수정하거나 항목을 추가·삭제합니다. | 수정 내용과 항목별 검토 완료 상태를 저장합니다. | 선행 업무는 체크박스로 선택하고 제안 사유·근거 확인. 직접 추가 항목은 AI 제안과 구분 |
| 7 | 모든 항목을 검토 완료로 표시하고 변경 저장 후 확정합니다. | 최신 문서 기준으로 작성되고 모든 항목이 검토된 체크리스트를 확정합니다. | 항목 검토 완료는 인수 업무 수행 완료와 구분 |
| 8 | 인수자가 확정된 문서와 체크리스트를 확인합니다. | 확정 후에만 내용과 근거를 조회할 수 있도록 합니다. | 인수자는 생성·수정·검토·확정 불가 |
| 9 | 수정이 필요하면 인계자가 검토를 다시 엽니다. | 확정을 해제하고 항목별 검토 상태를 초기화합니다. 재확정 전까지 인수자의 내용 조회를 제한합니다. | 재생성 중 이전 초안을 숨기고 실패 시 복원. 성공 시 새 초안으로 교체하고 기존 일정·수행 상태·서명 초기화 |

입력 예시

인수인계 제목·담당 업무·기간·인수자 정보와 운영 매뉴얼·업무 절차서·업무 관리 대장 등의 DOCX·XLSX·PPTX 파일. TXT·MD도 지원합니다.

기대 출력

문서에서 추출한 체크리스트 초안, 항목별 관련 문서 근거와 선행 업무 제안, 전임자가 검토·확정한 체크리스트

성공 기준

- 핵심 업무를 초안에서 확인하고 관련 문서 근거를 조회할 수 있습니다.
- 전임자의 수정 사항이 확정 체크리스트에 반영됩니다.
- 생성 또는 검증에 실패한 결과가 기존 체크리스트를 덮어쓰거나 확정 결과로 저장되지 않습니다.
- 인수자는 확정 전 문서·초안을 조회하거나 등록·수정·검토·확정할 수 없습니다. 확정 후에는 문서와 체크리스트·근거를 조회할 수 있습니다.

### 시나리오 2: 체크리스트를 바탕으로 일정 작성

- ID: SC-002
- 상황: 어떤 순서와 일정으로 인수인계할지 정해야 합니다.
- 목표: 시스템이 중요도와 선후관계를 고려해 생성한 일정표를 전임자가 검토·확정합니다.
- 사전 조건: 체크리스트와 기간이 정해져 있고 일정 계산에 필요한 업무 정보와 휴일·주말 정책이 준비되어 있습니다.

AI 활용

AI가 인계자가 확정한 업무의 중요도와 선후관계에 따라 순서·배치 이유를 제안합니다. 프로그램은 남은 배치 가능일에 업무 수를 가급적 균등하게 분배하고 날짜·휴일·선행 조건을 검사합니다. 업무별 1시간이나 하루 최대 건수를 고정하지 않습니다. 시작일이 과거이면 오늘부터 배치하고, 같은 날 선후행 업무가 있으면 선행 업무부터 진행하도록 안내합니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 전임자가 인수인계 기간을 확인하고 시스템에 일정 생성을 요청합니다. | AI가 업무 순서·배치 이유를 제안하고 프로그램이 확정된 선후관계와 주말·휴일 조건에 맞춰 날짜를 배정합니다. 생성 성공 시 입력 기간을 인수인계 기간에도 저장합니다. | 중요도·선행 업무는 체크리스트 검토 단계에서 확정 |
| 2 | 시스템이 작성한 일정표를 검토합니다. | 일요일~토요일 순서의 월간 달력에 중요도·선후행 업무 수와 일정을 표시합니다. 일요일과 설정한 휴일은 빨간색으로 표시합니다. | 조건을 만족하지 못하면 조정 필요 사항 안내 |
| 3 | 필요하면 카드를 드래그하거나 오른쪽 상세 패널에서 인수인계 날짜를 선택합니다. | 변경안을 반영하고 기간·휴일·선후관계 조건을 다시 검사합니다. 상세 패널은 달력 위 오른쪽에 겹쳐 열고 닫을 수 있도록 합니다. | 전임자의 수동 조정 |
| 4 | 검토한 일정을 확정합니다. | 후임자가 조회·수행할 일정으로 저장하고 확정 후에도 월간 달력을 표시합니다. | 확정 후 진행 관리에 활용 |

입력 예시

저장된 체크리스트·인수인계 기간과 업무별 중요도·선행 조건 등 일정 작성 정보, 전임자의 일정 조정 내용

기대 출력

체크리스트 항목과 연결된 일정 초안 및 전임자가 확정한 일정표

성공 기준

- 항목이 일정과 연결되고 선행 업무보다 후속 업무가 먼저 배치되지 않습니다.
- 휴일·주말 정책과 전임자의 조정 내용을 반영합니다.
- 조건을 만족할 수 없으면 정상 일정으로 확정하지 않고 사용자에게 알립니다.

### 시나리오 3: 인수인계 수행과 진행 상황 관리

- ID: SC-003
- 상황: 후임자가 체크리스트와 일정에 따라 업무를 익히고 있습니다.
- 목표: 수행할 업무와 남은 업무를 확인하고 진행 상태를 기록합니다.
- 사전 조건: 체크리스트와 일정이 확정되어 있고 후임자에게 권한이 있습니다. Google Calendar 등록 시 연동 권한이 필요합니다.

AI 활용

후임자가 자연어로 완료 처리나 캘린더 등록을 요청하면 AI가 수행할 작업과 대상 항목을 제안합니다. 사용자가 내용을 확인한 후 실행합니다. 권한 확인·완료 상태 저장·진행률 계산·캘린더 등록은 프로그램이 처리합니다. 화면에서 항목을 직접 선택하는 방식도 제공합니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 후임자가 대시보드를 확인합니다. | 진입 시 인수인계 현황을 표시합니다. 완료 수·진행률·남은 기간·분류별 진행 현황을 보여주고 분류를 펼치면 해당 업무 목록과 체크리스트 이동을 제공합니다. | 저장된 완료 상태 기준 |
| 2 | 업무 항목을 선택합니다. | 관련 문서와 근거를 보여주고 원문 조회·다운로드를 제공합니다. | 해당 인수인계 자료로 제한 |
| 3 | 수행한 항목을 선택하거나 ‘오늘 일정 완료 처리’처럼 요청합니다. | 자연어 요청은 AI가 대상과 작업으로 해석합니다. 사용자가 제안된 변경을 확인하면 프로그램이 권한·대상·최신 상태를 검사한 뒤 완료 상태를 저장하고 진행 현황을 갱신합니다. | 대상이 불명확하면 확인 요청 |
| 4 | 일정 화면에서 개인 Google 계정을 연결한 뒤 일정 전체 또는 일부를 선택하거나 자연어로 등록을 요청합니다. | 사용자가 확인한 확정 일정을 종일 일정으로 등록하고 항목별 결과를 표시합니다. 동일 항목 재등록은 기존 이벤트를 갱신합니다. | 중복 방지, 일부 실패 구분 |

입력 예시

후임자가 선택한 항목과 완료 상태, ‘오늘 일정 완료 처리’와 같은 요청, 캘린더에 등록할 일정 선택

기대 출력

갱신된 체크리스트·대시보드, 자연어 작업의 수행 결과, 캘린더 등록 결과

성공 기준

- 완료 상태와 진행률이 화면을 다시 열어도 유지됩니다.
- 자연어 요청으로 처리한 항목과 결과를 확인할 수 있습니다.
- 대상 업무가 불명확한 요청은 임의로 완료 처리하지 않고 확인합니다.
- 캘린더 등록의 성공·실패를 구분하고 동일 일정의 중복 등록을 방지합니다.

### 시나리오 4: 문서 기반 질문과 전임자의 추가 설명

- ID: SC-004
- 상황: 후임자가 업무 처리 절차나 운영 방법을 확인해야 합니다.
- 목표: 문서 근거 답변을 받고 부족한 설명은 전임자에게 확인합니다.
- 사전 조건: 검색 가능한 문서가 등록되어 있고 전임자·후임자에게 해당 인수인계 접근 권한이 있습니다.

AI 활용

AI가 질문과 이전 대화의 맥락을 파악하고 관련 문서를 검색한 결과로 답변을 작성합니다. 검색 결과가 없으면 질문 표현을 보완해 한 번 더 검색합니다. 충분한 근거를 찾지 못하면 그 한계를 알립니다. 전임자의 직접 답변은 사람이 작성한 답변으로 표시하며, AI 답변으로 바꾸어 표시하지 않습니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 후임자가 새 대화를 시작하거나 왼쪽 대화 목록에서 이전 대화를 선택해 질문합니다. | 질문 범위와 대화 맥락을 확인하고 관련 문서를 검색·재정렬합니다. | 해당 인수인계 범위로 검색 |
| 2 | 답변과 출처를 확인합니다. | AI가 검색한 문서에 근거해 답변합니다. 검색 결과가 없으면 검색어를 보완해 1회 재검색하고, 근거가 부족하면 답변 한계를 알립니다. | 저장된 답변을 재사용할 때도 인수인계·문서 조건 확인 |
| 3 | 필요한 경우 후속 질문을 하거나 이전 대화를 다시 엽니다. | 최근 대화와 이전 대화 요약을 활용해 맥락을 이어가며 답변과 대화를 저장합니다. | 인수인계·대화 구분 |
| 4 | AI 답변의 ‘인계자에게 추가 확인 요청’을 선택합니다. | 원 질문·AI 답변·근거를 연결해 요청을 저장하고 중복 요청을 방지합니다. | 후임자가 등록 |
| 5 | 전임자가 답변 대기·완료 목록에서 질문을 열고 답변합니다. | 답변과 시각을 기록하고 답변 완료 상태로 변경합니다. | 전임자의 직접 답변 |
| 6 | 후임자가 원래 대화 또는 인계자 답변 확인 화면에서 답변을 확인합니다. | 답변 내용과 상태를 보여줍니다. | AI 답변과 전임자 답변을 구분 |

입력 예시

후임자의 업무 절차·운영 방법에 관한 질문과 추가 설명 요청, 전임자가 직접 작성한 답변

기대 출력

문서 근거 답변과 출처, 근거 부족 안내, 추가 확인 질문과 전임자 답변, 저장된 대화 내역

성공 기준

- 답변과 출처가 일치하며 문서에서 확인할 수 없는 내용을 사실처럼 답하지 않습니다.
- 후속 질문에서 대화 맥락을 활용하고 다른 인수인계의 자료를 섞지 않습니다.
- 추가 확인 질문과 전임자 답변이 연결되고 후임자가 답변 상태를 확인할 수 있습니다.

### 시나리오 5: 인수인계 문서 출력과 서명 반영

- ID: SC-005
- 상황: 전임자가 인수인계 내용을 문서로 남기거나 전달해야 합니다.
- 목표: 정리한 내용을 서명과 함께 인수인계 문서로 내려받습니다.
- 사전 조건: 체크리스트와 일정이 확정되어 있고 전임자에게 출력 권한이 있습니다.

AI 활용

AI가 생성하고 전임자가 검토·확정한 체크리스트와 일정을 산출물로 활용합니다. 출력 단계에서는 확정 내용을 정해진 양식에 넣고 서명을 반영하며, AI가 내용을 다시 작성하거나 변경하지 않습니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 전임자가 확정 내용을 확인하고 본인 성명을 입력한 뒤 동의합니다. | 서명 입력을 검증하고 문서에 사용할 내용을 준비합니다. | 성명·사용자·서명 시각·확정 내용 연결 기록. 인증서 전자서명과 구분 |
| 2 | 문서 출력을 실행합니다. | 내용·일정·서명을 반영한 DOCX를 제공합니다. | DOCX 다운로드 |

입력 예시

저장된 인수인계 내용과 일정, 전임자가 제공하는 서명 정보

기대 출력

인수인계 내용·일정·서명이 반영된 DOCX 파일

성공 기준

- 저장된 내용과 서명이 내려받은 문서에 반영됩니다.
- 한글 텍스트와 표를 읽을 수 있으며 파일이 정상적으로 열립니다.

### 시나리오 6: 진행 상황에 따른 일정 재조정 — 고도화

- ID: SC-006
- 상황: 예정된 업무가 끝나지 않아 후속 인수인계 일정에 영향을 줍니다.
- 목표: 실제 진행 상황을 반영한 남은 일정의 수정안을 확인하고 확정합니다.
- 사전 조건: 기존 일정과 완료 상태가 저장되어 있고 남은 업무의 선후관계를 확인할 수 있습니다.

AI 활용

AI가 미완료 업무가 후속 일정에 미치는 영향을 고려해 남은 업무의 수정안과 변경 이유를 제안합니다. 프로그램은 완료 업무 유지·날짜·선후관계 조건을 검사합니다. 생성 중에는 진행 화면을 표시하고 실패하면 기존 일정을 복원합니다. 성공하면 기존 일정을 새 초안으로 교체하며 인계자의 확정 이후 인수자가 수행할 일정으로 사용합니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 전임자가 현재 진행 상태와 재조정에 사용할 정보를 확인합니다. | 완료·미완료 업무와 남은 기간·선후관계를 확인합니다. | 전임자가 기간·주말·휴일 조건을 확인한 뒤 수동 실행 |
| 2 | 제시된 수정안과 변경 사유를 검토합니다. | AI가 남은 업무의 수정안과 변경 이유를 제안합니다. 프로그램이 완료 업무를 유지하고 미완료 업무를 남은 배치 가능일에 분배합니다. 새 초안과 배치 사유를 월간 달력에 표시합니다. | 기간 내 배치가 어려우면 사유 안내 |
| 3 | 필요한 내용을 조정하고 확정합니다. | 일정 조건을 검증하고 확정한 수정안을 반영합니다. | 생성 실패 시 기존 일정 유지. 성공 시 새 초안을 검토·확정 |

입력 예시

저장된 일정과 완료 상태, 남은 업무의 선후관계, 전임자가 확인·수정한 일정 조건

기대 출력

남은 업무의 일정 수정안, 변경된 항목과 사유, 전임자가 확정한 일정

성공 기준

- 완료 업무를 변경하지 않고 남은 업무의 선후관계를 지킵니다.
- 기간 내 배치가 불가능한 경우 임의로 기한을 늘리거나 완료 처리하지 않고 사유를 알립니다.
- 생성에 실패하면 기존 일정과 기간을 유지하며, 성공한 새 초안은 전임자가 확정한 후 인수자 진행 화면에 반영됩니다.

## 작성 참고 — 공통 조건

- 문서 처리 한도는 인수인계당 10개, Office 파일당 10MB, TXT·MD 파일당 500KB, 추출 텍스트 합계 45,000자, PPT 합계 20장입니다. 문서 형식은 확장자로 구분합니다.
- Word·Excel의 미추출 영역과 PPT 판독 제한을 안내합니다. 근거 조회에는 추출 텍스트·장표 정리 내용·PPT 변환 이미지를 사용하고 원본 파일 다운로드를 제공합니다.
- 중요도는 높음·보통·낮음입니다. 선행 업무는 실제 인수 준비 조건이 필요한 경우에만 AI가 제안하고 인계자가 체크리스트 검토 단계에서 수정·확정합니다.
- 휴일은 사용자가 지정합니다. 공휴일 자동 조회나 Google Calendar 양방향 자동 동기화를 전제하지 않습니다. 개인 계정 OAuth 동의가 필요하며 서버 재시작 후 재연결합니다.
- 인계자 답변을 문서 RAG에 자동 편입하지 않습니다. 체크리스트 재생성으로 사라진 항목의 기존 Google 일정 삭제는 별도 확인이 필요합니다.
- Task 2의 KPI는 별도 모의 평가로 측정합니다. 위 성공 기준은 사용자 흐름의 동작 확인 기준이며 현장 효과 측정 결과를 뜻하지 않습니다.
