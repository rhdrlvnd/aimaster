# Task 3 — 시나리오 수립

- 수정일: 2026-10-20
- 과제명: 업무 인수인계 Agent
- 상태: 사용자 시나리오와 입출력·성공 기준 정의. 직접 제작한 예시 문서와 시나리오로 검증

## 1. 핵심 사용자 시나리오

모든 시나리오는 직접 제작한 업무 문서와 인수인계 데이터로 개발·평가합니다. 전임자(인계자)와 후임자(인수자)의 역할을 나누어 실행하고, AI가 제안한 결과와 사용자가 확정한 결과를 구분합니다. 평가 시에는 테스트 계정으로 인계자·인수자의 역할별 동작을 검증합니다. 전체 목록은 볼 수 있으나 상세 내용은 지정된 참여자만 접근합니다. 인수자는 확정된 내용만 조회하며 문서 등록이나 체크리스트 검토·수정 권한이 없습니다.

### 시나리오 1: 업무 문서로 인수인계 체크리스트 작성

- ID: SC-001
- 상황: 전임자가 담당 업무를 넘기기 위해 여러 업무 문서를 정리해야 합니다.
- 목표: 문서에서 인수인계할 핵심 업무를 추출하고 검토해 체크리스트를 확정합니다.
- 사전 조건: 인수인계 제목·담당 업무·기간·인수자 정보와 업무 문서가 준비되어 있고, 인계자 계정으로 접속했습니다. 문서 분석과 초안 생성을 위한 AI 연결이 설정되어 있습니다.

AI 활용

AI가 문서를 요약하고, 저장된 전체 문서 청크와 PPT 이미지를 바탕으로 후임자에게 전달할 업무를 정리합니다. 생성한 초안은 프로그램의 형식·인용 검사를 거친 뒤 별도 AI 호출로 누락·중복·설명과 근거의 일치 여부를 재검토합니다. 검증 실패 시 직전 초안과 구체적인 이유를 전달해 다시 작성합니다. AI 재검토가 정확성을 보장하지는 않으며 업무 내용의 최종 판단은 인계자가 담당합니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 인계자가 인수인계 제목·담당 업무·기간·인수자를 입력합니다. | 본인을 인계자로 지정한 인수인계를 생성하고 자료를 구분해 저장합니다. | 생성한 사용자를 인계자로 지정 |
| 2 | 업무 문서 화면에서 하나 이상의 파일을 선택해 등록합니다. | 형식·용량을 검사하고 파일별로 텍스트·표를 추출합니다. PPT는 슬라이드 이미지로도 변환합니다. | 파일 확장자로 형식 확인 |
| 3 | 문서별 분석 진행 상황과 결과를 확인합니다. | AI 요약 → 청크 분할 → 벡터 임베딩 → ChromaDB 저장을 수행하고 실제 처리 결과를 표시합니다. | 분석 실패 문서는 다시 분석 가능 |
| 4 | 모든 문서의 분석이 끝나면 체크리스트 생성을 실행합니다. | 전체 문서 청크와 PPT 이미지를 활용해 업무 항목과 근거를 생성합니다. | 진행 중인 단계 옆에 모델명과 진행 설명 표시 |
| 5 | 생성·검토 진행 상황을 확인합니다. | 프로그램이 형식·언어·인용·청크 연결·동일 제목 중복을 검사하고 AI가 내용을 재검토합니다. 통과한 초안을 저장합니다. | 검증 실패 시 최대 2회 재시도. 끝까지 실패하면 기존 초안 유지 |
| 6 | 원문 근거를 확인하고 제목·설명·분류·중요도를 수정하거나 항목을 추가·삭제합니다. | 수정 내용과 항목별 검토 완료 상태를 저장합니다. | 직접 추가한 항목은 AI 제안과 구분하고 근거 유무 표시 |
| 7 | 모든 항목을 검토 완료로 표시하고 변경 저장 후 확정합니다. | 최신 문서 기준으로 작성되고 모든 항목이 검토된 체크리스트를 확정합니다. | 항목 검토 완료는 인수 업무 수행 완료와 구분 |
| 8 | 인수자가 확정된 문서와 체크리스트를 확인합니다. | 확정 후에만 내용과 근거를 조회할 수 있도록 합니다. | 인수자는 생성·수정·검토·확정 불가 |
| 9 | 수정이 필요하면 인계자가 검토를 다시 엽니다. | 확정을 해제하고 항목별 검토 상태를 초기화합니다. 재확정 전까지 인수자의 내용 조회를 제한합니다. | 새 초안을 생성하려면 현재 내용 교체 확인. 실패 시 현재 내용 유지 |

입력 예시

인수인계 제목·담당 업무·기간·인수자 정보와 운영 매뉴얼·업무 절차서·업무 관리 대장 등의 DOCX·XLSX·PPTX 파일. TXT·MD도 지원합니다.

기대 출력

문서에서 추출한 체크리스트 초안, 항목별 관련 문서 근거, 전임자가 검토·확정한 체크리스트

성공 기준

- 핵심 업무를 초안에서 확인하고 관련 문서 근거를 조회할 수 있습니다.
- 전임자의 수정 사항이 확정 체크리스트에 반영됩니다.
- 생성 또는 검증에 실패한 결과가 기존 체크리스트를 덮어쓰거나 확정 결과로 저장되지 않습니다.
- 인수자는 확정 전 문서·초안을 조회하거나 등록·수정·검토·확정할 수 없습니다. 확정 후에는 문서와 체크리스트·근거를 조회할 수 있습니다.

### 시나리오 2: 체크리스트를 바탕으로 일정 작성

- ID: SC-002
- 상황: 어떤 순서와 일정으로 인수인계할지 정해야 합니다.
- 목표: 시스템이 중요도와 선후관계를 고려해 생성한 일정표를 전임자가 검토·확정합니다.
- 사전 조건: 체크리스트와 기간이 정해져 있고 일정 계산에 필요한 업무 정보와 휴일·주말 정책이 준비되어 있습니다.

AI 활용

AI가 확정한 업무의 중요도와 선후관계를 고려해 일정 초안을 제안합니다. 프로그램은 날짜·휴일·선행 업무 조건을 검사하고 전임자는 일정을 조정·확정합니다. 업무별 소요 기간을 확보하는 방식은 상세 설계에서 정하며, 필요한 값이 없으면 사용자 확인 없이 사실처럼 확정하지 않습니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 전임자가 인수인계 기간을 확인하고 시스템에 일정 생성을 요청합니다. | 확정 체크리스트를 바탕으로 AI가 업무 중요도·선후관계와 기간 조건을 반영한 일정 초안을 생성합니다. | 중요도는 확정 체크리스트 값 활용. 소요 기간·선후관계 입력 방식은 추가 확인 |
| 2 | 시스템이 작성한 일정표를 검토합니다. | 날짜와 휴일·선행 조건을 검사한 일정 초안을 화면에 표시합니다. | 조건을 만족하지 못하면 조정 필요 사항 안내 |
| 3 | 필요하면 업무별 날짜를 이동하거나 수정합니다. | 변경한 일정을 저장하고 선후관계 등 조건을 다시 검사합니다. | 전임자의 수동 조정 |
| 4 | 검토한 일정을 확정합니다. | 후임자가 조회·수행할 일정으로 저장합니다. | 확정 후 진행 관리에 활용 |

입력 예시

저장된 체크리스트·인수인계 기간과 업무별 중요도·선행 조건 등 일정 작성 정보, 전임자의 일정 조정 내용

기대 출력

체크리스트 항목과 연결된 일정 초안 및 전임자가 확정한 일정표

성공 기준

- 항목이 일정과 연결되고 선행 업무보다 후속 업무가 먼저 배치되지 않습니다.
- 휴일·주말 정책과 전임자의 조정 내용을 반영합니다.
- 조건을 만족할 수 없으면 정상 일정으로 확정하지 않고 사용자에게 알립니다.

### 시나리오 3: 인수인계 수행과 진행 상황 관리

- ID: SC-003
- 상황: 후임자가 체크리스트와 일정에 따라 업무를 익히고 있습니다.
- 목표: 수행할 업무와 남은 업무를 확인하고 진행 상태를 기록합니다.
- 사전 조건: 체크리스트와 일정이 확정되어 있고 후임자에게 권한이 있습니다. Google Calendar 등록 시 연동 권한이 필요합니다.

AI 활용

후임자가 자연어로 완료 처리나 캘린더 등록을 요청하면 AI가 수행할 작업과 대상 항목을 해석해 해당 기능을 호출합니다. 권한 확인·완료 상태 저장·진행률 계산·캘린더 등록은 프로그램이 처리합니다. 화면에서 항목을 직접 선택하는 방식도 제공합니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 후임자가 대시보드를 확인합니다. | 일정·목록·진행률·남은 기간·카테고리별 달성률을 표시합니다. | 저장된 완료 상태 기준 |
| 2 | 업무 항목을 선택합니다. | 관련 문서와 근거를 보여주고 원문 조회·다운로드를 제공합니다. | 해당 인수인계 자료로 제한 |
| 3 | 수행한 항목을 선택하거나 ‘오늘 일정 완료 처리’처럼 요청합니다. | 자연어 요청은 AI가 대상과 작업으로 해석합니다. 프로그램이 권한과 대상 항목을 확인한 뒤 완료 상태를 저장하고 진행 현황을 갱신합니다. | 대상이 불명확하면 확인 요청 |
| 4 | 필요하면 일정 전체 또는 일부를 선택하거나 자연어로 캘린더 등록을 요청합니다. | 등록할 일정을 확인해 Google Calendar에 등록하고 항목별 결과를 표시합니다. | 중복 방지, 일부 실패 구분 |

입력 예시

후임자가 선택한 항목과 완료 상태, ‘오늘 일정 완료 처리’와 같은 요청, 캘린더에 등록할 일정 선택

기대 출력

갱신된 체크리스트·대시보드, 자연어 작업의 수행 결과, 캘린더 등록 결과

성공 기준

- 완료 상태와 진행률이 화면을 다시 열어도 유지됩니다.
- 자연어 요청으로 처리한 항목과 결과를 확인할 수 있습니다.
- 대상 업무가 불명확한 요청은 임의로 완료 처리하지 않고 확인합니다.
- 캘린더 등록의 성공·실패를 구분하고 동일 일정의 중복 등록을 방지합니다.

### 시나리오 4: 문서 기반 질문과 전임자의 추가 설명

- ID: SC-004
- 상황: 후임자가 업무 처리 절차나 운영 방법을 확인해야 합니다.
- 목표: 문서 근거 답변을 받고 부족한 설명은 전임자에게 확인합니다.
- 사전 조건: 검색 가능한 문서가 등록되어 있고 전임자·후임자에게 해당 인수인계 접근 권한이 있습니다.

AI 활용

AI가 질문과 이전 대화의 맥락을 파악하고 관련 문서를 검색한 결과로 답변을 작성합니다. 검색 결과가 없으면 질문 표현을 보완해 한 번 더 검색합니다. 충분한 근거를 찾지 못하면 그 한계를 알립니다. 전임자의 게시판 답변은 사람이 작성한 답변으로 표시하며, AI 답변으로 바꾸어 표시하지 않습니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 후임자가 업무 절차나 장애 대응 방법을 질문합니다. | 질문 범위와 대화 맥락을 확인하고 관련 문서를 검색·재정렬합니다. | 해당 인수인계 범위로 검색 |
| 2 | 답변과 출처를 확인합니다. | AI가 검색한 문서에 근거해 답변합니다. 검색 결과가 없으면 검색어를 보완해 1회 재검색하고, 근거가 부족하면 답변 한계를 알립니다. | 저장된 답변을 재사용할 때도 인수인계·문서 조건 확인 |
| 3 | 필요한 경우 후속 질문을 하거나 이전 대화를 다시 엽니다. | 최근 대화와 이전 대화 요약을 활용해 맥락을 이어가며 답변과 대화를 저장합니다. | 인수인계·대화 구분 |
| 4 | 추가 설명이 필요하면 게시판에 질문을 등록합니다. | 질문을 저장하고 답변 대기 상태로 표시합니다. | 후임자가 등록 |
| 5 | 전임자가 질문에 답변합니다. | 답변과 시각을 기록하고 답변 완료 상태로 변경합니다. | 전임자의 직접 답변 |
| 6 | 후임자가 게시판 답변을 확인합니다. | 답변 내용과 상태를 보여줍니다. | AI 답변과 전임자 답변을 구분 |

입력 예시

후임자의 업무 절차·운영 방법에 관한 질문과 추가 설명 요청, 전임자가 직접 작성한 답변

기대 출력

문서 근거 답변과 출처, 근거 부족 안내, 게시판 질문과 전임자 답변, 저장된 대화 내역

성공 기준

- 답변과 출처가 일치하며 문서에서 확인할 수 없는 내용을 사실처럼 답하지 않습니다.
- 후속 질문에서 대화 맥락을 활용하고 다른 인수인계의 자료를 섞지 않습니다.
- 게시판 질문과 전임자 답변이 연결되고 후임자가 답변 상태를 확인할 수 있습니다.

### 시나리오 5: 인수인계 문서 출력과 서명 반영

- ID: SC-005
- 상황: 전임자가 인수인계 내용을 문서로 남기거나 전달해야 합니다.
- 목표: 정리한 내용을 서명과 함께 인수인계 문서로 내려받습니다.
- 사전 조건: 출력할 내용과 일정이 저장되어 있고 전임자에게 출력 권한이 있습니다.

AI 활용

AI가 생성하고 전임자가 검토·확정한 체크리스트와 일정을 산출물로 활용합니다. 출력 단계에서는 확정 내용을 정해진 양식에 넣고 서명을 반영하며, AI가 내용을 다시 작성하거나 변경하지 않습니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 전임자가 내용을 확인하고 서명을 입력합니다. | 서명 입력을 검증하고 문서에 사용할 내용을 준비합니다. | 서명 방식·양식은 추가 확인 |
| 2 | 문서 출력을 실행합니다. | 내용·일정·서명을 반영한 DOCX를 제공합니다. | DOCX 다운로드 |

입력 예시

저장된 인수인계 내용과 일정, 전임자가 제공하는 서명 정보

기대 출력

인수인계 내용·일정·서명이 반영된 DOCX 파일

성공 기준

- 저장된 내용과 서명이 내려받은 문서에 반영됩니다.
- 한글 텍스트와 표를 읽을 수 있으며 파일이 정상적으로 열립니다.

### 시나리오 6: 진행 상황에 따른 일정 재조정 — 고도화

- ID: SC-006
- 상황: 예정된 업무가 끝나지 않아 후속 인수인계 일정에 영향을 줍니다.
- 목표: 실제 진행 상황을 반영한 남은 일정의 수정안을 확인하고 확정합니다.
- 사전 조건: 기존 일정과 완료 상태가 저장되어 있고 남은 업무의 소요 기간·선후관계를 확인할 수 있습니다.

AI 활용

AI가 미완료 업무가 후속 일정에 미치는 영향을 고려해 남은 업무의 수정안과 변경 이유를 제안합니다. 프로그램은 완료 업무 유지·날짜·선후관계 조건을 검사합니다. 전임자가 수정안을 확정하기 전에는 실제 일정을 바꾸지 않습니다.

상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|---|---|---|---|
| 1 | 전임자가 현재 진행 상태와 재조정에 사용할 정보를 확인합니다. | 완료·미완료 업무와 남은 기간·선후관계를 확인합니다. | 자동 제안 또는 수동 실행 여부는 후속 설계 |
| 2 | 제시된 수정안과 변경 사유를 검토합니다. | AI가 남은 업무의 수정안과 변경 이유를 제안합니다. 프로그램이 완료 업무 유지·선후관계 등 조건을 검사하고 기존 일정과의 차이를 보여줍니다. | 기간 내 배치가 어려우면 사유 안내 |
| 3 | 필요한 내용을 조정하고 확정합니다. | 일정 조건을 검증하고 확정한 수정안을 반영합니다. | 확정 전에는 기존 일정 유지 |

입력 예시

저장된 일정과 완료 상태, 남은 업무의 소요 기간·선후관계, 전임자가 확인·수정한 일정 조건

기대 출력

남은 업무의 일정 수정안, 변경된 항목과 사유, 전임자가 확정한 일정

성공 기준

- 완료 업무를 변경하지 않고 남은 업무의 선후관계를 지킵니다.
- 기간 내 배치가 불가능한 경우 임의로 기한을 늘리거나 완료 처리하지 않고 사유를 알립니다.
- 전임자가 확정하기 전에는 기존 일정이 변경되지 않으며 확정한 내용이 진행 화면에 반영됩니다.

## 작성 참고 — 추가 확인 사항

- 일정 재조정의 실행 시점, 남은 업무 소요 기간 입력 방식과 캘린더 갱신 방식은 후속 설계에서 정합니다. SC-006은 2026-10-12 선택한 고도화이며 기본 일정 흐름 구현 후 개발하는 순서를 제안합니다.

- 문서 처리 한도는 인수인계당 10개, Office 파일당 10MB, TXT·MD 파일당 500KB, 추출 텍스트 합계 45,000자, PPT 합계 20장입니다. 문서 유형은 따로 입력하지 않습니다. 체크리스트 작성·검토 기준은 시스템 프롬프트에 정의하며 별도의 업무 용어집 업로드 기능은 없습니다.
- 근거 조회에는 추출 텍스트와 PPT 변환 이미지를 활용합니다. Office 원본 파일 다운로드는 SC-003의 문서 조회·다운로드 흐름에 포함합니다.
- 체크리스트의 중요도는 높음·보통·낮음으로 구분합니다. 복잡도·선행 조건 등 일정에 필요한 정보는 일정 수립 단계에서 확인하도록 설계합니다.
- 중요도는 AI가 제안하고 인계자가 수정·확정합니다. 일정에 필요한 소요 기간과 선후관계를 누가 입력하거나 어떻게 추정할지는 정해야 합니다. AI는 초안 제안, 프로그램은 일정 조건 검사, 전임자는 최종 확정을 담당하는 방향으로 설계하며 세부 알고리즘은 상세 설계에서 정합니다.
- 서명 입력 방식과 출력 문서 양식은 상세 설계에서 정합니다.
- 게시판 답변을 이후 RAG 검색 자료로 자동 반영하는 기능은 확정하지 않았습니다.
- Task 2의 정량 목표는 설정했으며, 평가 표본과 세부 실험 조건은 별도로 정합니다. 본 문서의 성공 기준은 개별 사용자 흐름의 동작 확인 기준입니다.
