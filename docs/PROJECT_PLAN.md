## 3. 기본 기획 자료의 방향

전임자가 업무 문서를 등록하면 AI가 인수인계 체크리스트 초안을 만들고, 전임자가 검토·확정한다. 확정한 체크리스트의 중요도와 선후관계를 고려해 AI가 일정 초안을 작성하는 흐름으로 기획한다. 전임자가 일정을 검토·확정하며, 후임자는 체크리스트와 일정으로 인수인계를 진행하고 문서 근거 Q&A를 활용한다. 추가 설명이 필요하면 후임자가 게시판에 질문하고 전임자가 직접 답변한다. 일정 작성에서 AI와 일반 계산 로직의 역할은 상세 아키텍처 확인 후 정한다.

자료에는 일정 생성·관리, Google Calendar 연동, 질문 게시판, 인수인계 문서 출력·서명도 포함되어 있다. 사용자는 아직 필수 범위를 확인하지 않았으나 전체 구현이 필요할 것으로 이해하고 있다. 이에 전체 기능 구현을 기본안으로 계획하되, 공식적으로 확인된 필수 범위와는 구분한다. 임의로 기능을 제외하지 않고 사용자와 협의한다.

사용자는 부문 과제에서 고도화를 통해 본인의 기여를 더 드러내기를 원한다. 2026-10-12 ‘진행 상황에 따른 일정 재조정’을 고도화 방향으로 선택했다. 미완료 업무와 남은 기간·선후관계를 고려해 AI가 수정안을 제안하고 전임자가 검토·확정한다. 완료 업무는 유지하며 기간 내 배치가 어려운 경우 그 사유를 보여준다. 실행 시점, 소요 기간 정보, 캘린더 갱신 방식은 후속 설계에서 정한다. 다른 후보는 포함하지 않는다.

자료는 총 12주 계획을 제시한다. 기존 AI Master의 8주 진행과 어떻게 맞출지 확인해야 한다. Q&A 정확도 93.8%, 캐시 응답 시간 88% 단축, 병렬 Map 처리 약 2배는 자료에 기재된 수치이며 우리 프로젝트의 실적이나 확정 목표가 아니다. 검증 실패 시 최대 2회 재시도는 처리 규칙으로 구분한다.

사용자가 추후 선명한 구현 아키텍처 이미지를 제공할 예정이다. 현재 이미지의 작은 글씨를 근거로 세부 기술을 확정하지 않는다. Task 1에는 React 화면, Python 문서 처리, LangGraph·LLM·RAG 기반 AI 처리를 우선 선택안으로 작성했다. 이는 새 과제의 기능과 사용자 경험에 맞춘 초안이며 DB·모델·서버 프레임워크 등의 상세 선택은 보류한다.

Task 1의 목표는 기본 기획 전체 기능의 사용자 흐름 구현과 선택한 일정 재조정 고도화다. 2026-10-13 정량 목표를 체크리스트 작성 시간 단축, 인수인계 소요 시간 단축, 전임자에게 직접 확인해야 하는 질문 감소, 기한 내 인수인계 완료율의 4개로 선택했다. 기존 후보 2·3번은 하나의 인수인계 소요 시간 목표로 통합하되 경과 기간과 실제 투입 시간을 혼합하지 않는다. 목표 수치는 작성 시간 50% 이상 단축, 인수인계 소요 시간 20% 이상 단축, 직접 확인 질문 40% 이상 감소, 기한 내 완료율 90% 이상으로 정했다. 인수인계 소요 시간은 경과 업무일 수로 측정한다. 현재 수준은 사용자 요청에 따른 기획상 예상값으로 작성 시간 120분, 인수인계 10업무일, 직접 확인 질문 20건, 기한 내 완료율 70%를 설정했다. 실제 평균 통계나 측정값은 아니며 평가 시 직접 기록한 기준선으로 비교한다. 체크리스트 포함 여부와 답변 정확성은 품질 확인 기준으로 유지한다. 일정 재조정은 완료 업무 유지, 선후관계 준수, 전임자 확정 후 반영 여부를 검증한다. 제출 양식의 ‘8주 목표’는 유지하되 원자료의 12주 계획과의 차이는 일정 설계 시 확인한다.

이 결정은 모든 추가 아이디어의 구현을 뜻하지 않는다. 사내 문서 시스템 연동·문서 변경 영향 안내 등 향후 확장 제안은 별도 선택 전까지 구현 범위에 자동 편입하지 않는다. 일정은 도전적인 상태이며 기능별 구현·검증 상태와 실제 장애 요인을 근거로 진행 상황을 공유한다. 사용자 승인 없이 기능을 삭제하거나 시연용 대체 동작을 완성 기능으로 표시하지 않는다.

사용자가 남은 기간을 6주로 전달했다. 현재 작업 공간에서 확인되는 것은 기획 문서와 참고 이미지이며 실행 가능한 애플리케이션 코드는 아직 확인되지 않는다. 전체 기능을 운영 수준으로 완성한다고 약속하기에는 범위가 크다. 입력 자료와 시연 조건을 정한 PoC는 검토할 수 있지만 주당 투입 시간, 사용 가능한 문서, API·외부 연동 환경과 구현 깊이에 따라 달라진다.

주요 불확실성은 문서 파싱·검색 품질, 일정의 소요 기간·선후관계 처리, Google Calendar 권한·연동, 서명·출력 양식이다. 사용자에게 익숙한 React 화면보다 이 부분을 먼저 작은 흐름으로 검증할 필요가 있다. 선명한 아키텍처 자료와 필수 구현 범위도 아직 확인이 필요하다.

조건부 계획 초안은 1주차 문서·API 확인 및 업로드부터 AI 결과까지 연결, 2주차 체크리스트·RAG, 3주차 검토·일정·진행 관리, 4주차 게시판·캘린더·출력·서명 연결, 5주차 일정 재조정과 통합 테스트, 6주차 오류 수정·평가·발표 준비다. 완료 보장 일정이 아니며 1주차 결과로 재산정한다. 외부 연동 가능 여부는 1주차에 먼저 확인한다. 지연 시 조정 후보는 사용자와 논의하며 임의로 기능을 삭제하지 않는다.

캘린더 연동·서명·출력·자연어 작업 실행 등의 후순위 여부는 사용자 선택이 필요하다. 개발 시간 일부는 통합 오류 수정·평가·시연 준비에 남겨 둔다. 기능 변경 없이 화면만 간소화하는 것으로 현재 일정 문제를 해결할 수 있다고 가정하지 않는다.

Task 1~3은 범위 합의 전까지 기능을 삭제하지 않는다. 실제 효과 지표의 현장 검증 가능 여부도 함께 재검토하며, 실제 관찰하지 못한 효과를 달성 실적으로 표현하지 않는다.

Google Calendar 검토 보완: 사용자는 AI 개발 도구와 함께 연동을 구현할 계획이며 캘린더를 쉽게 제외할 필요가 있는지 지적했다. 개인 캘린더 일정 생성은 API 키만으로 처리하지 않고 사용자 OAuth 동의와 쓰기 권한이 필요하다. 연결·등록 코드는 함께 구현할 수 있으며, 사용자는 자신의 Google 계정 로그인·권한 동의를 진행한다. 공식 근거: [일정 생성](https://developers.google.com/workspace/calendar/api/guides/create-events), [권한 범위](https://developers.google.com/workspace/calendar/api/auth).

PoC 연동안은 테스트 계정으로 연결해 사용자가 선택한 확정 일정을 등록하고, 등록 결과와 이벤트 ID를 저장해 중복 등록을 막는 수준이다. 이는 기존 기획의 연동을 제한된 환경에서 먼저 검증하는 안이다. 양방향 자동 동기화는 현재 확정한 요구가 아니며 복잡한 운영 요구를 전제로 난이도를 부풀리지 않는다. 회사 계정 사용 시 정책에 따른 연결 가능 여부를 확인한다. 실제 연결 전에는 성공 여부나 소요 시간을 단정하지 않는다.

- 이미지에서 읽기 어려운 내용은 추측하지 않고 해당 부분의 선명한 이미지나 설명을 요청한다.
