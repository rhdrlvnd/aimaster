# 프로젝트 개요

## 프로젝트명

업무 인수인계 Agent. 흩어진 업무 문서를 바탕으로 인수인계 체크리스트·일정 초안을 만들고, 문서 근거 Q&A로 후임자의 업무 습득을 지원하는 웹 서비스입니다.

## 해결하려는 문제

- 전임자: 운영 매뉴얼·인터페이스 정의서·발표 자료에 흩어진 정보를 다시 읽으며 전달할 내용을 처음부터 정리합니다. 본업과 겹치는 시기라 사람마다 빠뜨리는 내용이 다릅니다.
- 후임자: 필요한 내용을 찾지 못해 같은 질문을 반복하고, 그때마다 전임자의 업무가 끊깁니다.
- 조직: 핵심 업무나 장애 대응 절차가 빠지면 업무 적응이 늦어지고, 문제 발생 시 대응도 지연됩니다.

## 기술 스택

React, FastAPI, Python, LangGraph, Pydantic, ChromaDB, SQLite, 사내 AI API(생성 gpt-6.1-sol, 임베딩 text-embedding-3-large), Google OAuth/Tasks API를 사용했습니다.

## 주요 기능

문서 등록·분석, 체크리스트 생성·검토, 선행 업무 제안, 일정 계획·재조정, 문서 근거 Q&A, 진행 현황 관리, 문서 출력 기능을 구현했습니다.

체크리스트 생성에는 **Orchestrator–Workers**를 적용해 업무를 계획하고 나눠 작성한 결과를 통합하며, **Evaluator–Optimizer**로 초안의 누락·중복·근거를 평가하고 필요한 항목을 보완합니다. AI가 만든 결과는 서버 코드가 형식·원문 인용·선행 관계를 검사한 뒤에만 저장하고, 최종 확정은 인계자가 합니다.

## 기대 효과

전임자는 처음부터 정리하는 대신 AI 초안을 검토하는 데 집중하고, 후임자는 문서 근거가 붙은 답변으로 스스로 업무를 익힙니다. 이를 통해 체크리스트 작성 시간·인수인계 기간·전임자 직접 질문을 줄이고 기한 내 인수인계 완료를 지원하는 것이 목표입니다. 테스트 결과는 아래 KPI 달성도에 측정 조건과 함께 정리했습니다.


# 서비스 아키텍처

## 프론트엔드

React 기반 화면에서 인계자·인수자·관리자 역할별로 문서 등록, 체크리스트 검토, 월간 일정, 업무 채팅, 진행 현황을 제공합니다. 긴 생성 작업은 진행 상태를 실시간으로 표시합니다.

## 백엔드 API

FastAPI가 참여자·역할 권한 검사, AI 호출, 결과 검증, 저장, 외부 연동을 담당합니다. 데이터 버전(revision) 검사로 오래된 생성 결과가 최신 내용을 덮어쓰지 않도록 합니다.

## Agent 오케스트레이션

LangGraph와 서버 로직이 문서 분석, 체크리스트 작성·검토, 선행 관계 판단, 일정 계획, Q&A 흐름을 제어합니다. 역할 분담 원칙은 다음과 같습니다.

- AI: 어떤 업무를 넣을지, 근거가 어디인지, 어떤 순서로 배울지와 그 이유를 판단합니다.
- 코드: 응답 형식, 문서·장표 ID 존재 여부, 인용의 원문 일치, 선행 관계 순환, 기간·휴일에 맞춘 날짜 배정처럼 정답이 정해진 확인과 계산을 맡습니다.
- 사람: 인계자가 체크리스트·선행 관계·일정을 검토하고 확정합니다.

## 데이터 저장소

SQLite는 인수인계 정보·문서 메타데이터·체크리스트·일정·대화·AI 사용량을, ChromaDB는 문서 청크와 임베딩을 저장합니다. 별도 DB 서버 없이 서비스 서버에 저장합니다.

## 외부 연동

Google OAuth로 사용자 동의를 받아 확정된 인수인계 업무를 Google Tasks에 등록하고, 매일 오전 6시(한국 시간)에 완료·미완료 상태를 양방향으로 동기화합니다. Google 토큰은 암호화해 저장합니다.

## 핵심 데이터 흐름

1. 인계자가 업무 문서를 등록하면 서버가 텍스트·표를 추출하고, PPT 슬라이드 이미지는 문서 분석 Agent가 해석합니다.
2. 추출·분석 결과를 청킹·임베딩하여 ChromaDB에 저장하고, 문서 메타데이터와 처리 상태는 SQLite에 기록합니다.
3. Orchestrator–Workers: LLM이 전체 문서를 비교해 업무 목록을 정하면, 서버가 검증 후 업무를 2개씩 묶어 Worker에 배정합니다(최대 2묶음 동시 실행). 각 Worker는 전체 문서와 전체 업무 목록을 참고해 맡은 항목을 작성하고, 서버가 식별자와 순서를 확인해 통합합니다.
4. Evaluator–Optimizer: 코드가 형식과 원문 인용을 먼저 검사하고, 검토 Agent가 누락·중복·근거 적절성을 평가합니다. 지적 사항이 있으면 작성 Agent가 해당 항목을 보완하고 다시 검토합니다. 묶음 작성은 최대 5회, 통합 후 보완은 최대 5회이며, 끝까지 통과하지 못하면 기존 자료를 유지합니다.
5. 선행 업무 검토 Agent가 준비 조건에 따른 관계를 제안합니다. AI는 기존 근거의 ID만 고르고, 서버가 원문을 연결한 뒤 자기 참조·중복·순환 여부를 검사해 초안을 저장합니다.
6. 인계자가 체크리스트와 선행 관계를 검토·확정하면 AI가 일정 순서와 이유를 제안하고, 서버가 기간·휴일·선행 조건에 맞춰 날짜를 배정합니다. 인계자가 일정을 확정하면 인수자가 진행 상태를 기록합니다.
7. 업무 Q&A는 질문과 관련된 문서 청크를 ChromaDB에서 검색해 답변과 출처를 제공합니다. 추가 설명이 필요하면 인계자에게 질문을 전달합니다.


# 핵심 기능 및 Agent 구현 내용

## 대표 사용자 시나리오 (실제 실행 기준)

1. 입력: 인계자가 인사 업무 예시 문서 7개(Word·Excel·PowerPoint)를 등록합니다.
2. 분석: 서버가 텍스트·표를 추출하고, PPT 장표는 문서 분석 Agent가 이미지로 해석해 정리합니다.
3. 체크리스트 생성: 업무 목록 선정 → 2개씩 분할 작성 → 코드 검사·검토 Agent 평가·보완을 거쳐 체크리스트 34개와 선행 관계 3개를 저장했습니다. 문서 분석 이후 생성·검증에 247.4초(4분 7초)가 걸렸습니다.
4. 검토·확정: 인계자가 각 항목의 원문 근거를 확인하며 수정·확정합니다.
5. 일정: AI가 학습 순서와 이유를 제안하고, 서버가 인수인계 기간·휴일·선행 조건에 맞춰 날짜를 배정합니다. 인계자가 확정한 일정은 Google Tasks로 등록할 수 있습니다.
6. 업무 습득: 인수자는 일정에 따라 진행 상태를 기록하고, 궁금한 점은 채팅으로 질문해 답변과 출처 문서를 함께 확인합니다. 문서로 답할 수 없으면 인계자에게 질문이 전달됩니다.

## 핵심 기능

### 문서 등록·분석

Word·Excel은 텍스트와 표를 추출하고, PPT는 슬라이드 이미지를 분석해 후속 생성에 사용할 정리 내용을 저장했습니다.

### 체크리스트 생성·검토

Orchestrator–Workers 구조로 전체 문서에서 업무 목록을 계획하고, 서버가 배정한 묶음별로 상세 내용을 작성한 뒤 결과를 통합했습니다. Evaluator–Optimizer로 초안의 누락·중복·근거 적절성을 평가하고, 지적 사항을 반영해 보완·재검토했습니다. 인용문은 공백만 정리한 뒤 원문과 글자 단위로 대조하고, 맞지 않으면 저장하지 않고 다시 작성하게 합니다.

### 선행 업무·일정 계획

선행 업무 검토 Agent가 문서 근거를 바탕으로 필수 준비 조건을 연결하고, 서버가 관계와 근거를 검증합니다. 일정 계획 Agent는 업무 순서와 배치 이유를 제안하며, 프로그램이 기간·휴일·선행 조건을 반영해 일정을 배치하고 검사합니다.

### 문서 근거 Q&A

질문 임베딩과 문서 검색을 통해 근거 기반 답변을 생성하고, 부족한 경우 인계자 확인으로 연결합니다. 체크리스트 생성은 문서 간 조건을 놓치지 않도록 전체 청크를 참고하고, Q&A는 질문과 관련된 부분만 검색합니다.

## 주요 Agent 구현

### 문서 분석 Agent

PPT 장표 내용을 해석하고 판독 제한을 함께 정리합니다.

### 체크리스트 작성·검토 Agent

업무 추출, 설명 작성, 근거 연결, 누락·중복 검토를 역할 분리 방식으로 구현했습니다. 같은 모델을 쓰되 프롬프트로 작성과 검토의 역할·판단 기준을 나눴습니다.

### 선행 업무 검토 Agent

문서에서 확인되는 권한·환경·지식·준비 결과를 바탕으로 선행 관계를 제안합니다. 기존 인용의 참조 ID를 선택하면 서버가 원문을 연결하고 자기 참조·중복·순환 관계를 검사합니다.

### 일정 계획·업무 Q&A Agent

확정 업무 기반 일정 제안과 문서 검색 기반 답변, 자연어 작업 제안을 담당합니다. 자연어로 요청한 완료 처리나 Google Tasks 등록은 사용자 확인과 서버의 대상·권한 검사를 거쳐 실행합니다.

## 사용 기술/라이브러리

- LangGraph — 작성·검사·검토·보완 흐름의 분기 제어
- FastAPI — API, 권한 검사, 서버 오케스트레이션
- React — 사용자 화면 구현
- ChromaDB — 문서 임베딩 저장 및 검색
- SQLite — 메타데이터, 상태, 대화 저장
- Pydantic — 구조화 응답 검증
- python-docx/openpyxl/python-pptx — 문서 처리
- Google OAuth·Tasks API — 외부 일정 연동

## 생성 품질·안정성 지표 (개발 중 실모델 실행 로그)

- 저장 성공률: 한 번에 전체를 생성하던 방식은 4회 모두 약 260초 후 HTTP 502로 실패(0%), 업무 분할 후 6회 모두 검증·저장 완료(100%).
- 검토 Agent 지적: 같은 6회 실행의 통합 검토에서 누락·중복·근거 문제 26건을 지적하고 해당 항목만 보완했습니다. 라운드별 합계라 같은 항목이 중복 집계됐을 수 있습니다.
- 원문 불일치 근거: 원문에 없는 인용·잘못된 장표 근거 7건을 저장 전에 차단하고 재작성했습니다. 저장된 결과의 원문 불일치는 0건입니다.
- 자동 테스트: 2026년 11월 6일 체크리스트 생성 18개, 선행 관계 8개, API 오류·재시도 5개로 구성된 테스트 31개를 실행해 모두 통과했습니다. AI 응답과 HTTP 오류를 모의 처리한 프로그램 검증입니다.

## 검증 범위

- 실제 모델로 실행해 확인: 인사·개발 문서의 체크리스트·선행 관계 생성·검증·저장, 테스트 인수인계 3건과 질문 20건.
- 모의 응답 자동 테스트로 확인: 인용·근거 검증, 순환 관계 차단, 누락·중복 식별자 차단, 재시도 횟수 제한, 429 대기 시간 반영, Google Tasks 연동 로직.
- 아직 확인하지 않음: 실제 현장 문서와 실제 후임자 대상 효과, 실제 Google 계정의 장기 동기화(일일 배치 포함), 대규모 동시 접속·장기 운영, 체계적인 프롬프트 인젝션 방어 평가.


# 기술 문제 해결 과정

### 긴 체크리스트 생성 시 응답 잘림과 서버 오류

1. 문제 상황: 문서 7개에서 업무 30개 이상을 한 번에 작성하게 하자 출력 한도에 걸려 응답이 잘렸고, 4회 모두 약 260초 후 HTTP 502로 실패했습니다. 이후 HTTP 429 요청 제한 오류도 발생했습니다.
2. 원인: 한 요청에서 많은 업무를 상세하게 작성하면서 출력 분량이 커졌고, 실패 시 다시 생성해야 하는 범위도 넓었습니다. 문서별로 나눠 보내는 방법은 문서 사이의 준비 조건·예외 사항을 놓칠 수 있어 택하지 않았습니다.
3. 해결 방법: **Orchestrator–Workers** 구조로 전체 문서에서 업무 목록을 먼저 계획했습니다. 서버가 업무를 2개씩 배정하고 최대 2개 묶음을 동시에 처리하며, 각 Worker는 전체 문서 맥락을 유지한 채 담당 항목을 작성합니다. 실패한 묶음만 다시 쓰고, 출력이 잘리면 출력 한도를 늘린 뒤 그래도 잘리면 한 업무씩 나눠 재작성합니다. 일시적 오류(429·502·503·504)는 한 번만 재시도하고, 429는 서버가 안내한 대기 시간을 반영합니다.
4. 결과: 분할 후 실모델 6회 실행이 모두 검증·저장까지 완료됐습니다(분할 전 0/4 → 분할 후 6/6). 대신 전체 문서를 반복 전달하므로 입력 토큰은 늘어났습니다. 묶음 크기별 비교는 같은 조건으로 하지 않아 향후 측정 과제로 남겼습니다.

### 근거 연결과 업무 누락 문제

1. 문제 상황: 응답 형식은 맞아도 업무가 누락·중복되거나, 설명을 뒷받침하지 못하는 근거가 연결됐습니다. AI가 원문을 바꿔 인용하거나 없는 장표를 근거로 드는 경우도 있었습니다.
2. 원인: 응답 구조와 참조 ID가 유효한지만 검사해서는 업무 내용의 누락이나 근거의 의미적 적절성을 판단하기 어려웠습니다. 인용 정확성은 AI 스스로 확인하게 하면 같은 오류를 반복할 수 있었습니다.
3. 해결 방법: **Evaluator–Optimizer** 패턴으로 검토 Agent의 지적 사항을 작성 Agent에 전달해 보완·재검토하도록 구성했습니다. 인용은 코드가 공백만 정리한 뒤 원문과 글자 단위로 대조하고, 장표 근거는 실제 장표 번호와 연결되는지 검사합니다. Pydantic으로 응답 형식도 함께 검사합니다.
4. 결과: 6회 실행에서 검토 Agent가 26건을 지적해 해당 항목을 보완했고, 원문 불일치 근거 7건을 저장 전에 차단해 저장 결과의 원문 불일치는 0건입니다. 별도 검증 실행에서는 통합 검토 지적 1건에 대한 보완·재검토 후 저장 성공을 확인했습니다. 최종 검증에 실패한 결과는 기존 체크리스트를 덮어쓰지 않습니다. 다만 원문을 요약한 인용도 차단되는 엄격함은 감수했습니다.

### 선행 관계와 결과 연결 오류

1. 문제 상황: AI가 배정된 업무의 제목을 바꾸거나 선행 관계 근거를 다시 작성하면서 결과 연결과 인용 검증에 실패했습니다.
2. 원인: 제목 문자열로 업무를 식별하는 방식과 AI가 근거를 자유롭게 재서술하는 방식에서 연결 오류가 발생했습니다.
3. 해결 방법: 작성 결과는 **target_id**로 배정된 업무와 연결하고, 선행 관계 근거는 기존 인용의 **evidence_ref**를 선택하면 서버가 원문을 연결하도록 변경했습니다. 관계 대상·자기 참조·중복·순환 여부는 별도 코드로 검사했습니다.
4. 결과: 잘못된 업무 식별자와 유효하지 않은 관계를 차단하고, 인사 문서의 선행 관계 3개와 개발 문서의 선행 관계 6개를 검증·저장했습니다.

### 배운 점

AI에게 더 많은 일을 맡기는 것보다, 한 번에 쓸 양을 줄이고 · 검토를 별도 단계로 두고 · 정답이 정해진 확인과 계산은 코드에 맡기는 설계가 결과를 안정적으로 만들었습니다. 세 문제 모두 "AI가 자유롭게 쓰게 한 부분"에서 생겼고, AI의 판단 범위를 좁히고 코드가 확인하게 바꾸면서 해결됐습니다.


# 향후 개선 및 확장 방향

## 현재 한계

- 검증 규모: 직접 만든 예시 문서(분야별 7개), 테스트 인수인계 3건, 질문 20건으로 측정한 초기 결과라 실제 현장 효과로 일반화할 수 없습니다.
- 내용 정확성: 자동 검사로 형식·참조 오류는 막지만, 업무가 빠짐없이 정리됐는지와 의미적 정확성은 보장하지 못합니다. 인계자의 최종 검토·확정이 필요한 이유입니다.
- 문서 처리: 문서 10개, Office 파일 10MB, 전체 45,000자, PPT 20장까지 처리합니다. Word·Excel의 일부 이미지·차트와 Word 머리글·각주는 추출하지 않고, PPT 이미지 해석은 오류 가능성이 있어 사람이 확인해야 합니다.
- 운영: 현재는 테스트 사용자 선택 방식으로 역할을 검증합니다. 사내 SSO, 대규모 동시 접속, 장기 운영은 검증하지 않았습니다.

## 단기 개선 (1~3개월)

- 1단계 평가 세트 구축: 부서별 필수 업무·질문·정답 근거를 정리해 체크리스트 누락률과 답변 정확도를 반복 측정합니다. 완료 기준은 두 지표의 기준선 확보입니다.
- 2단계 처리 방식 비교: 평가 세트로 Worker의 묶음 크기·동시 실행 수, 평가·보완 횟수를 바꿔 가며 누락률·처리 시간·토큰 사용량을 같은 조건에서 비교하고 기본값을 정합니다.
- 3단계 파일럿: 실제 인수인계를 기존 방식과 같은 업무 범위·완료 기준으로 비교하고, 사람 검토 시간까지 포함해 작성 시간을 측정합니다. 다음 단계 진입 조건은 기간 20% 이상 단축, 직접 질문 40% 이상 감소, 기한 내 완료율 90% 이상 유지입니다. 미달 지표는 원인을 분석해 해당 기능만 수정한 뒤 재측정합니다.
- 병행: 실제 Google 계정으로 등록·완료·연결 해제·배치 실패·재시작 사례를 검증하고, 개발 환경 재현 절차와 운영 설정을 정리합니다.

단기적으로는 "무엇이 얼마나 좋아졌는지"를 같은 조건에서 반복 측정할 수 있는 검증 체계를 먼저 갖추고, 그 결과로 처리 방식을 조정할 계획입니다.

## 장기 확장 (6개월+)

- 사내 SSO와 관리자 권한 체계, 감사 로그, 백업·복구 체계 연동
- 문서 변경 시 기존 체크리스트와 답변의 영향을 추적하고, 갱신안을 생성해 담당자가 검토·반영하는 기능 추가
- 부서별 업무 유형에 맞춘 평가 기준과 도메인 특화 기능 확장
- 대규모 동시 접속과 장기 운영 환경 검증

인수인계 이후에도 활용할 수 있는 문서 기반 Q&A를 바탕으로, 조직 차원의 업무 지식 공유와 변경 관리를 지원하는 플랫폼으로 확장할 계획입니다.
