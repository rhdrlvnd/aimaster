## 1. 최종 아키텍처 요약

- 완성된 아키텍처 핵심: React 화면과 FastAPI 서버를 기반으로 업무 문서 분석, 체크리스트 생성·검토, 선행 업무 검토, 일정 계획, 문서 근거 질의응답을 연결했습니다. 역할별 AI 처리와 LangGraph 워크플로우를 활용하고, SQLite에 업무 상태를 저장하며 ChromaDB에서 관련 문서 근거를 검색합니다.
- 최종 산출물 형태: 인계자·인수자·관리자가 역할에 따라 사용하는 웹 기반 업무 인수인계 서비스입니다. 별도의 인수인계 문서를 처음부터 작성하는 대신, 기존 업무 문서를 등록해 체크리스트와 일정의 초안을 만들고 검토·확정할 수 있습니다. 인수인계 이후에도 등록 자료와 문서 기반 채팅을 업무 지식 확인에 활용할 수 있습니다.
- Agent 구조: 문서 분석, 체크리스트 작성, 체크리스트 검토, 선행 업무 검토, 일정 계획, 업무 Q&A의 6개 역할로 구분했습니다. 역할별 프롬프트와 입출력을 분리하고 LangGraph와 서버 처리 흐름으로 연결합니다. 모든 역할이 자율적으로 상시 대화하는 방식이 아니라, 사용자의 실행 요청과 처리 단계에 따라 필요한 역할을 호출합니다.

| 구성 요소 | 역할 |
|---|---|
| React | 문서 등록·분석 결과, 체크리스트 검토, 월간 일정, 업무 채팅, 개인 및 관리자 진행 현황을 제공합니다. |
| FastAPI | 참여자·역할 권한 검사, AI 호출, 결과 검증, 데이터 저장, 외부 서비스 연동을 처리합니다. |
| 역할별 AI·LangGraph | 문서 내용 정리, 체크리스트 작성·검토, 선행 조건 판단, 일정 순서 제안, 검색 기반 답변을 수행합니다. 기본 생성 모델은 gpt-6.1-sol이며 환경 설정으로 변경할 수 있습니다. |
| SQLite | 인수인계 기본 정보, 문서 메타데이터, 체크리스트, 일정, 공유 진행 상태, 대화·답변, 서명 기록 등을 저장합니다. |
| ChromaDB | 문서를 나눈 청크와 임베딩을 저장하고 질문과 관련된 문서 근거를 검색합니다. 기본 임베딩 모델은 text-embedding-3-large입니다. |
| Google Tasks | 확정 업무를 사용자별 Google 계정에 등록하고, 매일 오전 6시(한국 시간)에 완료·미완료 상태를 양방향으로 동기화하도록 구현했습니다. |

주요 처리 흐름

1. 인계자가 Word·Excel·PowerPoint 등의 업무 문서를 등록합니다.
2. 텍스트·표를 추출하고 PPT는 슬라이드 이미지도 분석해 내용을 정리합니다. 검색에 사용할 청크와 임베딩을 저장합니다.
3. AI가 전체 문서 내용을 참고해 체크리스트를 작성하고, 별도의 검토 단계에서 누락·중복·근거와 선행 관계를 확인합니다. 서버 검증을 통과한 초안만 저장합니다.
4. 인계자가 체크리스트와 선행 관계를 검토·확정합니다. AI가 일정 순서와 이유를 제안하고, 프로그램이 기간·휴일·선행 관계를 반영해 업무를 배치합니다.
5. 인수자는 확정 자료와 일정을 확인하고 진행 상태를 기록합니다. 여러 인수자가 하나의 진행률을 공유하며 누구나 완료 처리할 수 있습니다.
6. 업무 질문은 관련 문서를 검색해 답변과 출처를 제공하고, 추가 설명이 필요하면 인계자에게 확인을 요청합니다.
7. 관리자는 전체 인수인계의 일정 준수·지연·종료 임박 현황을 확인하고, 개별 인수인계를 읽기 전용으로 조회합니다.

| 평가 지표 (KPI) | 목표 수치 (Task 2) | 실제 달성 수치 | 달성 여부 및 비고 |

## 3. 창출된 핵심 가치

### 3-1. 비즈니스 가치

- 기존 업무 문서의 활용: 운영 매뉴얼·업무 정의서·검토 자료 등을 입력해 인수인계 초안을 만들 수 있도록 하여, 인계자가 내용을 처음부터 다시 정리하는 부담을 줄일 수 있는 기반을 마련했습니다.
- 핵심 업무 전달과 확인: 문서 근거가 연결된 체크리스트를 인계자가 검토·보완하고 인수자가 수행 여부를 기록하도록 구성했습니다.
- 업무 지식 접근성 향상: 후임자가 문서 기반 채팅으로 필요한 절차와 근거를 찾고, 부족한 설명은 인계자에게 요청할 수 있습니다. 인수인계 이후에도 업무 지식 확인에 활용할 수 있습니다.
- 일정 관리의 가시성 확보: 관리자 화면에서 전체 인수인계의 지연·종료 임박·일정 미확정 여부를 확인할 수 있습니다. 여러 인수자가 참여하는 경우에도 공유 진행 상태를 한곳에서 관리합니다.

### 3-2. 기술적 가치

- 역할별 AI 처리 구조 구현: 문서 분석부터 작성·검토·일정·질의응답까지 역할을 분리하여 프롬프트와 검증 로직을 기능별로 개선할 수 있도록 구성했습니다.
- 근거 검증을 포함한 생성 처리: Pydantic으로 응답 형식을 검사하고, 별도 로직으로 문서·청크·인용문·선행 관계를 검증합니다. 잘못된 결과는 정상 초안으로 저장하지 않습니다.
- AI와 일반 프로그램의 역할 구분: 업무 내용 판단과 순서 제안은 AI가 수행하고, 권한·날짜 조건·순환 관계·저장 가능 여부는 프로그램에서 검사합니다.
- 실행 가능한 업무 지원: 자연어로 완료 처리나 Google Tasks 등록을 요청하면 대상과 변경 내용을 확인받은 뒤 서버에서 실행합니다.
- 생성 안정성 개선: 전체 문서 맥락을 유지하면서 출력할 업무를 작은 묶음으로 나누고, 제한 재시도와 최종 검증을 통해 긴 요청의 실패에 대응했습니다.


## 4. 운영 및 보안 고려 사항

- 인증 방식: 현재는 테스트 사용자 선택과 서버 세션으로 역할별 동작을 검증합니다. 운영 배포 시에는 사내 SSO 등 실제 사용자 인증으로 전환해야 합니다. Google 연동은 서비스 공통 OAuth 설정과 사용자별 동의를 사용합니다.
- 권한 통제: 서버에서 참여자와 역할을 검사합니다. 인계자는 문서·체크리스트·일정을 관리하고, 등록된 인수자는 공유 진행 상태와 본인 대화를 관리합니다. 관리자는 전체 현황과 개별 자료를 읽기 전용으로 조회하며, 내용 수정과 완료 처리는 할 수 없습니다.
- 데이터 구분: 인수인계별 자료를 구분하고, AI 대화와 Google 연결은 사용자별로 관리합니다. 검색 시 해당 인수인계에 속한 문서·인덱스인지 검사합니다.
- 비밀정보 관리: API 키와 OAuth 설정은 Git에서 제외한 환경 설정으로 관리합니다. Google 토큰은 암호화하여 저장하며, DB와 암호화 키가 포함된 데이터 폴더도 비밀정보로 취급합니다.
- Injection 대응: 문서·대화에 포함된 명령을 시스템 지시로 따르지 않도록 프롬프트를 구성하고, AI가 제안한 작업은 사용자 확인과 서버의 대상·권한 검사를 거칩니다. 별도의 공격 시나리오에 대한 정량 보안 평가를 완료한 것은 아닙니다.
- 장애 대응: 일시적인 API 오류에는 제한적으로 재시도하고, 최종 실패 시 기존 자료를 유지합니다. 데이터 버전 검사로 오래된 생성 결과가 최신 내용을 덮어쓰지 않도록 처리합니다.
- 외부 동기화 운영: Google Tasks 상태는 실시간이 아니라 매일 오전 6시에 반영합니다. 서버가 실행 중이어야 하며, 당일 미실행 배치는 서버 재시작 후 처리합니다. 상태 충돌·선행 조건 위반·삭제된 Task는 임의로 덮어쓰지 않고 확인할 내용을 표시합니다.


## 5. 회고 및 향후 확장

### 기술적 한계

- AI가 결과를 생성하는 것뿐 아니라 업무 단위를 적절히 나누고 근거를 정확하게 연결하는 것이 핵심 과제였습니다. 긴 설명, 업무 누락, 잘못된 인용과 선행 관계를 실제 결과와 비교하며 개선했습니다.
- 자동 검증으로 형식·참조 오류를 줄일 수 있지만 업무 내용의 완전성과 의미적 정확성을 보장하지는 못합니다. 인계자의 최종 검토가 필요합니다.
- 실제 업무 문서 대신 직접 제작한 예시 문서를 사용했으며, 개인 프로젝트로 평가했습니다. 실제 현장의 업무 적응·기간 단축 효과로 일반화하기 어렵습니다.
- Word·Excel의 일부 이미지·차트와 Word 머리글·각주 등은 추출하지 않습니다. PPT 이미지 분석도 해석 오류 가능성이 있어 사람이 확인해야 합니다.
- 대규모 동시 접속, 장기간 운영, 체계적인 프롬프트 인젝션 방어 평가는 추가 검증이 필요합니다.
- Google Tasks 연동은 코드와 모의 응답 기반 테스트를 수행했지만, 실제 계정에서 일일 배치까지 포함한 장기 동기화 검증은 별도로 필요합니다.
