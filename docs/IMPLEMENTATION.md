## 2. 문서 처리와 근거

- DOCX·XLSX는 추출된 전체 텍스트·표·위치를 보관한다. PPT는 변환 이미지·텍스트·발표자 노트를 AI에 전달해 장표별 전체 내용을 정리한다. 요약본을 원문 대신 사용하는 방식이 아니다.
- 체크리스트 생성에는 전체 저장 청크를 전달한다. PPT 이미지를 다시 전송하지 않는다. Q&A는 관련 청크를 검색·재정렬한다.
- 기본 청킹은 1,200자·중첩 160자다. PPT 해석 결과는 장표 위치와 연결한다. 기본 임베딩은 text-embedding-3-large이며 data/chroma에 저장한다.
- 화면의 추출 문자·청크·벡터 수는 처리 결과다. 분석 성공 후 새 인덱스를 활성화하며 이전 자료가 섞이지 않게 관리한다.
- 한도: 인수인계당 10문서, Office 10MB/파일, TXT·MD 500KB/파일, 추출 텍스트 합계 45,000자, PPT 합계 20장. PPT 이미지 변환에는 로컬 렌더러가 필요하다.
- Word 머리글·바닥글·각주·텍스트 상자와 Word·Excel 이미지·차트·SmartArt·원본 배치는 추출 범위 밖이다. Excel 숨김 시트·셀은 포함하고 수식은 계산하지 않고 문자열로 읽는다. PPT 이미지 해석의 누락·오독은 근거 화면에서 확인해야 한다.

## 3. 생성·검증·재시도

전체 목록 선정 후 두 업무씩 작성하며 최대 두 요청을 동시에 실행한다. 모든 요청은 전체 자료와 업무 목록을 유지한다. target_id로 응답 대상을 연결하고 서버가 원래 제목과 순서를 적용한다. 비슷한 제목을 임의로 대응시키지 않는다.

목록 선정과 묶음 작성은 최대 3회 시도한다. 출력 잘림·대상 연결 오류가 지속된 묶음은 한 업무씩 나누어 재작성한다. 전체 검토에서 문제 항목을 최대 4회 보완하며 보완 응답 검증은 최대 3회 시도한다. 제목 50자·설명 500자 이내의 간결한 초안을 요구한다. 기존 수동 작성 내용에 생성 규칙을 소급 적용하지 않는다.

선행 관계는 실제 인수 준비 조건에 한정한다. AI가 연결할 업무와 기존 인용의 evidence_ref를 선택하면 서버가 원문 인용을 연결하고 대상·중복·자기 참조·순환을 검사한다. 관계 개수는 고정하지 않는다. 모든 검증을 통과해야 저장하며 실패 시 기존 자료를 유지한다.

작성·검토 전송 헬퍼는 HTTP 429·502·503·504에 한 번 재시도한다. 502 계열은 3초, 429는 Retry-After를 제한 범위에서 반영하며 기본 대기 60초다. 이를 모든 문서 분석·Q&A 호출의 공통 정책으로 간주하지 않는다. AI 요청별 읽기 대기는 600초이며 전체 작업 시간은 여러 요청으로 더 길어질 수 있다.

## 4. 결과 교체와 사용자 흐름

- 인계자는 문서·체크리스트·일정을 편집·확정한다. 인수자는 확정 내용을 읽고 수행 상태를 기록한다. 검토를 다시 열면 재확정 전까지 인수자 조회를 제한한다.
- 인수인계 진입은 현황 화면으로 통일한다. 검토 완료는 인수 수행 완료가 아니다.
- 재생성 중 기존 결과를 숨기고 실패 시 복원한다. 체크리스트 생성 성공 시 이전 일정·수행 상태·서명을 초기화한다.
- 일정 생성 성공 시 기간과 새 초안을 함께 저장한다. 기존 확정 일정을 새 초안으로 교체하고 재확정한다. 재조정 시 완료 업무 날짜를 유지한다. 실패 시 기존 기간·일정은 유지한다.
- 일정은 시간 단위가 아닌 날짜별 업무 수 균등 배치를 사용한다. 과거 시작일이면 오늘 이후로 배치하고 선후관계 때문에 분배가 완전히 균등하지 않을 수 있다. 같은 날 선후행 업무를 허용하되 선행 업무부터 수행한다. 구형 일/시간 단위 데이터 처리 코드는 호환용이다.
- 같은 작업 공간의 메뉴 이동 중 체크리스트 생성 상태를 유지한다. 브라우저 종료·새로고침·서버 재시작 후 영속 작업 복구는 보장하지 않는다.
- 후임자의 추가 확인 요청에는 원 질문·AI 답변·근거를 연결한다. 인계자 답변은 원 대화에 표시하고 문서 RAG에 자동 반영하지 않는다. 자연어 변경 요청은 사용자 확인 후 서버에서 검사·실행한다.

## 5. Google Tasks와 실행 환경

실행 방법은 [README](../README.md)를 따른다. 서비스 공통 OAuth 클라이언트와 사용자별 로그인 동의를 사용한다. PKCE·일회용 state·사용자에 연결된 콜백 쿠키로 연결 요청을 확인한다. 개발용 콜백은 http://127.0.0.1:5185/api/calendar/callback이며 실제 설정과 Google 등록 URI가 같아야 한다.

확정 업무를 Google 기본 Tasks 목록에 등록하고 업무 시작 날짜를 기한으로 지정한다. 동일 사용자·Google 계정·인수인계·업무의 재등록은 같은 Task를 갱신하며 완료 상태를 초기화하지 않는다. Tasks 권한과 Google Tasks API 활성화가 필요하다. 기존 Calendar 연결 사용자는 다시 동의한다. Google 계정 식별자와 토큰은 SQLite에 암호화하여 저장하고 키는 data/google-oauth.key에 보관한다. DB와 키를 보존하면 서버 재시작 후에도 연결을 유지한다.

완료·미완료 상태는 매일 오전 6시(한국 시간)에 양방향으로 동기화한다. 백엔드가 실행 중이어야 하며 당일 오전 6시 이후 시작하면 미실행 배치를 한 번 처리한다. 실행 이력과 잠금은 DB에 보관하여 중복 실행을 막는다. 로컬의 진행 중 상태는 Google의 미완료에 대응하되 로컬 표시를 유지한다. 양쪽에서 다른 상태로 변경했거나 선행 업무 조건을 위반하는 완료·취소 요청은 반영하지 않고 확인할 항목으로 표시한다. Google에서 삭제한 Task를 임의로 재생성하거나 로컬 완료로 바꾸지 않는다. 실패한 항목은 다음 일일 배치에서 다시 확인한다. 화면은 로컬 DB의 처리 결과만 조회하며 Google을 상시 조회하지 않는다.

일정 화면에서 Tasks 등록 시 기존 이벤트 정리에 동의한 경우 Task 저장 성공 후 해당 사용자·인수인계·업무의 앱 이벤트만 확인해 삭제한다. 체크리스트 재생성으로 ID가 달라진 이전 이벤트와 Task, 다른 Google 계정의 자료는 자동 삭제하지 않는다. 날짜 변경 동기화는 포함하지 않는다. 테스트 사용자 전환 방식은 운영용 로그인·SSO가 아니다.

2026-11-02 검증: Google 응답을 대체한 테스트를 포함한 Tasks·기존 기능·워크플로우·균등 일정 테스트 61건, 프런트엔드 테스트 2건과 빌드를 통과했다. 등록 재시도, 중복 방지, 삭제·권한·동시 변경, 선행 관계, 상태 복원, 재시작 후 토큰 갱신과 일일 실행을 확인했다. 실제 Google 계정에서의 Tasks 등록·완료 왕복 확인은 별도로 필요하며 테스트 수치를 실서비스 성공률로 해석하지 않는다.

## 8. 관리자 AI 사용량 집계

관리자의 AI 사용량 화면은 한국 시간 기준 오늘·이번 달·최근 30일의 실제 API 요청을 집계한다. 입력·출력·캐시 입력·추론 토큰과 호출 수를 확인하고 일별·모델별·기능별·인수인계별·사용자별로 비교한다. 사용자별 집계는 요청을 실행한 사용자 ID를 기준으로 하며 현재 이름과 부서를 연결한다. 동명이인은 ID로 구분하고, 미등록 사용자와 요청 사용자 미확인 기록도 각각 유지한다. 캐시 입력은 입력 토큰에, 추론은 출력 토큰에 포함되므로 중복 합산하지 않는다.

문서 분석·임베딩·질의응답이 사용하는 `rag.request`와 체크리스트 작성·검토가 사용하는 `ai_transport.post`의 전송 단계에서 기록한다. 상위 Agent의 로그를 재집계하지 않으며, 각 HTTP 재시도와 검증에 실패한 응답도 관측된 사용량을 남긴다. 스트림과 병렬 실행에서도 요청의 인수인계·사용자 맥락을 유지한다. API가 사용량을 반환하지 않거나 응답을 받지 못한 경우는 미확인 건수로 구분한다.

사내 단가표가 없어 비용을 추정하지 않고 실제 API가 반환한 토큰량만 보여준다. 호출 수에는 문서·질문 임베딩 요청도 포함되며, 하나의 사용자 작업에서 발생한 여러 API 요청은 각각 집계한다. 사용량을 확인할 수 없는 요청은 0토큰으로 단정하지 않고 확인 건수와 미확인 건수를 함께 표시한다.

사용량 테이블은 업무 상태와 별도로 SQLite에 저장한다. 프롬프트·응답 본문·원문·인증정보는 저장하지 않는다. 관리자 API는 서버에서 역할을 검사한다. 기록 시작 전의 사용량은 기존 로그만으로 정확하게 복원할 수 없어 포함하지 않는다.

사용량 필드 기준은 [OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)와 [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)의 응답 명세를 확인했다. 사내 모델의 단가는 공개 가격으로 추정하지 않는다.
