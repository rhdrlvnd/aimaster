# Task 2 — 문제 정의 및 서비스 기획

- 수정일: 2026-10-26
- 상태: 제출 초안. 정량 목표 설정 완료, 세부 평가 방법 검토 중

## 1. 프로젝트 명

업무 인수인계 Agent

## 2. 배경 및 문제 정의

- 현재 상황(As-Is): 담당자가 변경되거나 신규 인력이 투입될 때 운영 매뉴얼, 인터페이스 정의서, 테이블 정의서 등 여러 문서를 확인해 업무를 인수인계합니다. 문서의 형식과 저장 위치가 분산되어 있어 전임자가 전달할 내용을 정리하고, 후임자가 필요한 정보를 찾는 데 부담이 발생합니다.
- Pain Point: 문서를 모으는 것만으로는 어떤 업무부터 익혀야 하는지, 무엇이 빠졌는지 확인하기 어렵습니다. 핵심 업무나 장애 대응 절차가 제대로 전달되지 않으면 후임자의 업무 적응과 운영 이슈 대응이 지연될 수 있습니다.
- 기회 요인: AI가 여러 문서에서 인수인계할 업무를 추출해 체크리스트 초안을 만들면 전임자는 정리 작업을 줄이고 내용 검토에 집중할 수 있습니다. 후임자는 문서 근거 Q&A로 필요한 정보를 찾고, 체크리스트와 일정을 통해 수행할 업무와 진행 상황을 확인할 수 있습니다.

## 3. 목표 사용자 (Target User)

- 전임자: 업무 문서를 등록하고, AI가 작성한 체크리스트와 일정을 검토·확정하며 후임자의 질문에 답변하는 담당자입니다.
- 후임자: 확정된 체크리스트에 따라 업무를 익히고 진행 상태를 기록하며, 문서 검색과 질문을 통해 필요한 지식을 확인하는 담당자입니다.
- 권한 구분: 인계자(전임자)만 문서 등록·삭제·분석과 체크리스트 생성·수정·검토·확정을 할 수 있습니다. 인수자(후임자)는 확정된 문서·체크리스트·근거를 조회합니다. 확정 전이거나 검토를 다시 연 상태에서는 준비 중 안내를 표시합니다. 전체 인수인계 목록은 볼 수 있지만 상세 내용은 지정된 참여자만 접근합니다.
- 사용 상황: 담당자 변경, 신규 인력 투입, 인수인계 이후 운영 이슈나 장애 발생 시 활용합니다.

## 4. 프로젝트 목표

### 정성적 목표

1. 업무 문서를 인수인계 체크리스트로 정리하여 전임자의 자료 정리 부담을 줄입니다.
2. 핵심 업무 누락 방지: 문서에서 추출한 체크리스트를 전임자가 검토·보완하고 수행 여부를 확인하여 중요한 업무가 인수인계에서 빠지지 않도록 지원합니다.
3. 후임자가 문서 근거 답변과 출처를 확인하여 필요한 업무 지식을 찾고 업무에 적응하도록 지원합니다.
4. 체크리스트와 일정의 진행 상태를 한눈에 확인하여 인수인계 서비스를 편리하게 이용할 수 있도록 합니다.
5. 운영 이슈·장애 대응 지연 위험 완화: 후임자가 관련 문서와 기존 질의응답에서 대응 절차를 확인하고, 부족한 설명은 전임자에게 질문하여 필요한 정보를 찾지 못해 대응이 늦어지는 위험을 줄입니다.

### 정량적 목표 (KPI)

아래 4개 지표를 목표로 설정합니다. 수치는 개발 후 검증할 목표이며 현재 측정된 성과가 아닙니다. 현재 수준은 기존 업무 문서가 있고 전임자 1명이 후임자 1명에게 한 담당 업무를 인계하는 상황을 가정한 예상값입니다. 실제 회사 평균 통계나 측정값은 아닙니다. 평가 시에는 직접 기록한 기존 방식의 결과로 비교합니다.

| 성과 지표 | 목표 수치 | 측정 방법 | 현재 수준(예상) |
|---|---|---|---|
| 체크리스트 작성 시간 단축률 | 기존 대비 50% 이상 단축 — 예상 기준 1시간 이하 | 동일한 문서와 완료 기준으로 수작업 작성·확정 시간과 AI 생성·검토·수정·확정 시간을 비교합니다. | 인수인계 1건의 체크리스트 작성·검토에 약 120분 |
| 인수인계 소요 시간 단축률 | 기존 대비 20% 이상 단축 — 예상 기준 8업무일 이하 | 같은 업무 범위와 인수 완료 기준으로 기존 방식과 Agent 활용 방식의 소요 시간을 비교합니다. 시작부터 완료 기준 충족까지 경과한 업무일 수로 측정합니다. | 인수인계 시작부터 완료까지 약 10업무일 |
| 전임자에게 직접 확인해야 하는 질문 감소율 | 기존 대비 40% 이상 감소 — 예상 기준 12건 이하 | 동일한 평가 질문을 기존 방식과 Agent 활용 방식으로 처리하고, 전임자의 추가 답변이 필요한 질문 수를 비교합니다. | 인수인계 1건당 전임자에게 직접 확인하는 질문 약 20건 |
| 기한 내 인수인계 완료율 | 90% 이상 | 처음 합의한 기한 안에 완료 기준을 충족한 인수인계 사례 수 ÷ 전체 평가 사례 수 × 100으로 계산합니다. | 기한 내 완료율 약 70% — 10건 중 7건 수준 |

평가 방법 초안

- 체크리스트 작성 시간에는 문서 확인·AI 생성 대기·검토·수정을 포함합니다. 양쪽 모두 동일한 핵심 업무가 포함된 사용 가능한 결과를 완료 기준으로 삼습니다.
- 인수인계 소요 시간은 시작부터 인수 완료까지의 경과 업무일 수로 평가합니다. 경과 업무일 수와 전임자·후임자의 실제 투입 시간을 합산하거나 같은 단위로 취급하지 않습니다. 주 측정 단위는 시작부터 완료까지의 경과 업무일 수로 정합니다. 실제 투입 시간은 이 값에 합산하지 않습니다. 체크리스트 작성 시간이 전체 소요 시간에 포함되면 두 단축 효과를 더하지 않습니다.
- 질문은 같은 업무 범위를 기준으로 준비하고 문서로 답할 수 있는 질문과 전임자의 설명이 필요한 질문을 함께 포함합니다. 동일 질문의 후속 대화는 하나의 질문으로 세며, AI가 응답했다는 이유만으로 해결됐다고 판정하지 않습니다. 내용과 근거가 맞고 추가 설명이 필요 없는지 확인합니다.
- 시간·질문 감소율은 (기존 값 − Agent 활용 값) ÷ 기존 값 × 100으로 계산합니다. 기존 값이 0이면 감소율을 계산하지 않고 건수 또는 시간을 그대로 제시합니다. 실제 사용에서는 전체 질문 수가 달라질 수 있으므로 직접 확인이 필요한 질문의 비율도 함께 확인합니다.
- 인수 완료는 버튼 클릭만으로 판정하지 않고 사전에 정한 업무 설명·실습 확인 등의 기준으로 판단합니다. 기간 내 완료율은 인수인계 사례 단위로 계산하며, 개별 체크리스트 항목 완료율과 구분합니다. 기한이 변경되더라도 최초 합의한 기한 기준 결과를 유지합니다.
- 일정 재조정의 기여는 같은 지연 상황에서 재조정을 사용한 경우와 사용하지 않은 경우를 비교할 수 있지만, 실제 현장 자료 없이 기한 내 완료율 개선을 단정하지 않습니다. 완료율 상승 폭을 제시할 때는 퍼센트포인트(%p)로 구분합니다.
- 개인 프로젝트로 혼자 평가하므로 인계자·인수자 역할을 번갈아 실행합니다. 질문 해결 여부는 사전에 정한 정답·근거 기준으로 판정하고, 실제 후임자의 이해도나 현장 기간 단축과 구분합니다.
- 실제 업무 문서 대신 직접 제작한 예시 문서와 평가 시나리오로 검증합니다. 결과는 모의 평가 결과로 구분하며 실제 현장 인수인계 기간·완료율의 개선으로 표현하지 않습니다. 질문 정답 여부와 체크리스트 필수 업무는 품질 확인 기준으로 유지하되 별도 대표 KPI로 세지 않습니다.

## 5. 핵심 기능 정의

항목의 검토 완료는 인계자의 내용 검토 상태이며, 후임자의 업무 수행 완료와는 다릅니다.

| 기능 | 처리 내용과 제공 결과 |
|---|---|
| 인수인계 생성·접근 권한 | 인계자가 제목·담당 업무·기간·인수자를 입력해 인수인계를 생성합니다. 전체 목록을 표시하고 상세 접근과 변경 권한은 참여 여부와 역할에 따라 제한합니다. |
| 업무 문서 등록·분석 | 인계자가 여러 업무 문서를 선택하면 파일별로 순차 처리합니다. 텍스트·표를 추출하고 PPT는 슬라이드 이미지도 분석합니다. 전체 내용 정리, 청크 분할, 임베딩, ChromaDB 저장을 진행하며 문서별 단계와 처리 결과를 표시합니다. 추출 내용과 PPT 변환 이미지를 분석 자료로 보관합니다. |
| 업무 추출·체크리스트 생성 | 모든 문서의 저장된 텍스트·표·PPT 장표 정리 내용을 바탕으로 업무 목록을 선정한 뒤 소수 항목씩 작성합니다. 각 요청에 전체 자료를 전달하며 이미지는 다시 보내지 않습니다. 형식·한국어·인용·근거 연결을 검사하고 AI가 누락·중복·정책 혼동을 재검토합니다. 문제가 있는 항목을 보완하고 전체 검토와 선행 업무 검증을 통과한 초안만 저장합니다. |
| 체크리스트 검토·확정 | 인계자가 제목·설명·분류·중요도·선행 업무를 수정하고 항목을 추가·삭제합니다. 텍스트 인용 또는 슬라이드 근거를 확인하고, 모든 항목의 검토 완료 상태를 저장한 뒤 확정합니다. 재생성 중에는 생성 진행 화면을 표시하고, 실패하면 기존 결과를 다시 표시합니다. 성공하면 새 초안으로 교체하고 기존 일정·수행 상태·서명을 초기화합니다. 확정 후에는 검토를 다시 열어야 수정할 수 있습니다. |
| 일정 수립·관리 | AI가 확정 체크리스트의 중요도와 선후관계에 따른 순서·배치 이유를 제안합니다. 프로그램이 남은 배치 가능일에 업무 수를 가급적 균등하게 분배합니다. 전임자는 월간 달력에서 드래그하거나 날짜를 선택해 조정·확정합니다. 후임자는 확정된 달력을 조회하고 개인 Google 계정 연결 후 전체 또는 일부 일정을 등록합니다. |
| 문서 근거 Q&A | 후임자의 질문과 관련된 문서를 검색하고 답변과 출처를 제공합니다. 검색 결과를 재정렬하고 필요 시 검색어를 보완합니다. 근거가 없거나 범위 밖인 질문은 답변 한계를 알립니다. |
| 대화 유지·자연어 실행 | 최근 대화와 요약으로 질문 맥락을 유지합니다. ‘오늘 일정 완료 처리’와 같은 요청을 해석하고 대상과 변경 내용을 보여줍니다. 사용자가 확인한 뒤 서버에서 권한·최신 상태를 검사해 실행합니다. |
| 진행 현황·인계자 답변 | 진입 시 인수인계 현황을 표시하고 분류별 진행 항목을 펼쳐 체크리스트로 이동하도록 합니다. 후임자는 채팅에서 추가 확인을 요청하고, 전임자는 질문 목록에서 원 질문과 AI 답변·근거를 확인해 답변합니다. 후임자는 원래 대화와 답변 확인 화면에서 이를 조회합니다. |
| 인수인계 문서 출력·서명 | 인계자가 본인 성명과 동의를 입력하면 확정 체크리스트·일정·근거·서명 기록을 DOCX로 출력합니다. 확정 내용 변경 시 다시 서명하도록 합니다. |

AI 역할은 문서 분석, 체크리스트 작성, 체크리스트 검토, 선행 업무 검토, 일정 계획, 업무 Q&A의 6개로 구분합니다. 업로드·권한 확인·진행률 계산·일정 조건 검사·저장 등은 일반 프로그램으로 처리합니다. 체크리스트 생성과 내용 재검토는 별도의 AI 처리 단계로 나누어 구성합니다. 역할별 프롬프트와 입출력을 분리하고 LangGraph와 서버 처리 흐름으로 연결합니다. 선행 업무는 인수를 진행하기 위한 실제 준비 조건이 있을 때만 제안하며 원문 근거를 함께 검증합니다. AI 재검토 결과만으로 업무 누락이 없거나 근거가 모두 정확하다고 보장하지 않으며 인계자가 최종 검토합니다.

## 6. 기대 효과

- 준비 부담 감소: 문서 기반 초안을 활용해 전임자의 체크리스트 작성 시간을 기존 대비 50% 이상 줄이는 것을 목표로 합니다.
- 인수인계 효율 향상: 자료 정리·검색·질의응답을 지원해 인수인계 소요 시간을 기존 대비 20% 이상 줄이는 것을 목표로 합니다.
- 전임자 문의 부담 감소: 후임자가 문서 근거 답변으로 해결할 수 있는 질문은 스스로 확인하고, 필요한 경우에 전임자의 추가 설명을 받습니다. 전임자에게 직접 확인해야 하는 질문을 기존 대비 40% 이상 줄이는 것을 목표로 합니다.
- 일정 준수 지원: 진행 상황과 지연 업무를 확인하고 남은 일정을 재조정하여 합의한 기한 안에 인수인계를 마치도록 지원하며, 기한 내 완료율 90% 이상을 목표로 합니다.

위 수치는 이번 프로젝트의 목표값이며, 측정 전 기대효과를 실제 성과로 표현하지 않습니다.

- 핵심 업무 누락 방지: 체크리스트와 전임자 검토를 통해 전달할 업무를 정리하고, 완료 상태를 확인하여 놓친 업무를 줄일 수 있습니다.
- 운영 이슈·장애 대응 지연 위험 완화: 필요한 대응 절차와 업무 지식을 쉽게 확인하여 후임자가 정보 부족으로 대응을 지연하는 상황을 줄일 수 있습니다.

## 7. 범위 및 제약사항

고도화 범위에는 진행 상황에 따른 일정 재조정을 포함합니다. 전임자가 재조정을 실행하면 완료 업무의 날짜를 유지하고 미완료 업무를 남은 배치 가능일에 분배합니다. 업무별 시간이나 하루 최대 건수를 고정하지 않습니다. 일정 화면의 기간은 인수인계 기간과 동일하며 새 초안 생성 성공 시 함께 저장합니다. 완료 업무 유지·선후관계 준수·전임자 확정 후 반영 여부를 검증하며, 고도화의 효과는 기한 내 인수인계 완료율과 연결해 확인합니다.

- In Scope: 전임자가 웹에서 인수인계와 문서를 등록하고 체크리스트와 일정을 검토·확정하며, 후임자가 이를 확인하고 인수인계를 수행하도록 구현합니다. 문서 근거 Q&A와 출처 확인, 대화 유지, 자연어 작업 실행, 진행 대시보드, 인계자 질문·답변, Google Calendar 연동, 문서 출력·서명을 포함합니다. 인수인계별 자료 구분과 역할별 접근 제어를 적용하며, 검색·캐시 등은 각 기능 요구사항에 맞춰 설계합니다.
- Out of Scope: 현재 계획한 기능과 일정 재조정 고도화 중 제외하는 기능은 없습니다. 전체 범위를 유지하며 구현 순서를 나누어 진행합니다.
- 제약사항: 실제 업무 문서를 활용할 수 없으므로 운영 매뉴얼·인터페이스 정의서·테이블 정의서 등의 예시 문서와 인수인계 시나리오를 직접 제작하여 개발·평가합니다. 평가 결과는 제작한 데이터의 범위에 한정되며 실제 현장에 적용했을 때의 효과와는 차이가 있을 수 있습니다.


문서 처리 및 평가 조건

- 역할별 동작은 테스트 계정으로 구분해 검증합니다. 서버에서 참여 여부와 인계자·인수자 권한을 확인하도록 설계합니다.
- DOCX·XLSX·PPTX·TXT·MD를 지원합니다. 인수인계당 최대 10개 문서, Office 파일당 10MB, TXT·MD 파일당 500KB, 추출 텍스트 합계 45,000자, PPT 합계 20장까지 처리합니다.
- Word의 머리글·바닥글·각주·텍스트 상자와 Word·Excel의 이미지·차트 등 추출하지 않는 영역은 사용자에게 안내합니다. Excel 수식은 계산 결과 대신 수식 문자열로 읽습니다. PPT는 이미지와 추출 텍스트·발표자 노트를 함께 분석하되 이미지 해석은 사람이 확인해야 합니다.
